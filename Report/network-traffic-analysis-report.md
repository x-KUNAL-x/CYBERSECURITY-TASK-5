## 3. Network Capture Setup

* Visiting websites through a web browser.
* Performing DNS lookups.
* Sending network requests to internet servers.

The traffic was captured for approximately **one minute**.

## 5. Stopping the Capture

After approximately one minute, the packet capture was stopped using Wireshark's **Stop** button.

The captured packets were then reviewed for protocol identification and analysis.

---

## 6. Protocol Filters Used

Wireshark display filters were used to identify different types of network traffic.

| Filter | Purpose               |
| ------ | --------------------- |
| `dns`  | Displays DNS traffic  |
| `http` | Displays HTTP traffic |
| `tcp`  | Displays TCP traffic  |
| `udp`  | Displays UDP traffic  |

These filters made it easier to isolate and analyze specific protocols.

---

## 7. Protocols Identified

### 🌐 DNS – Domain Name System

DNS is used to translate domain names into IP addresses.

For example, when a user enters a website address, DNS helps determine the IP address of the server hosting that website.

**Observation:** Several DNS queries were observed while accessing websites.

---

### 🌍 HTTP – Hypertext Transfer Protocol

HTTP is used to transfer web content between clients and web servers.

**Observation:** HTTP traffic was analyzed as part of the web browsing activity.

> Note: Modern websites commonly use HTTPS rather than plain HTTP. The exact protocols present depend on the traffic captured.

---

### 🔗 TCP – Transmission Control Protocol

TCP provides reliable, connection-oriented communication between devices.

**Observation:** TCP connections were observed between the computer and remote servers during network activity.

---

### 📡 UDP – User Datagram Protocol

UDP is a connectionless protocol designed for fast communication with low overhead.

UDP traffic may be generated by services such as DNS and other network applications.

## 9. Packet Information Observed

Wireshark provides several useful fields for analyzing captured packets:

| Field       | Description                           |
| ----------- | ------------------------------------- |
| Source      | Device or server sending the packet   |
| Destination | Device or server receiving the packet |
| Protocol    | Protocol used by the packet           |
| Length      | Size of the packet                    |
| Info        | Additional packet information         |
| Time        | Time at which the packet was captured |

## 11. Security and Privacy Considerations

Packet captures can contain sensitive network information such as:

* IP addresses
* Domain names
* Network metadata
* Device information
* Application-related traffic

Therefore, packet captures should only be performed on networks and devices that you are authorized to monitor.

Before uploading a `.pcap` file to a public GitHub repository, it should be reviewed for sensitive information.
